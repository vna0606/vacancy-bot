# TODO: retroactive edit/delete отправленных сообщений

## Проблема

Сейчас (2026-07-22) `sender.py` отправляет сообщения через `bot.send_message()` /
`_send_with_retry()`, но возвращаемый объект `Message` (с `.message_id`) нигде не
сохраняется. Из-за этого нет возможности задним числом отредактировать или удалить
уже отправленное пользователю сообщение (например, если вакансию нужно отозвать —
рекрутёр попросил снять публикацию, а она уже ушла подписчикам).

Telegram Bot API умеет `editMessageText` / `deleteMessage`, но требует знать
`chat_id` + `message_id` конкретного сообщения — API не даёт способа получить список
уже отправленных ботом сообщений постфактум.

## Что нужно сделать (не реализовано, ждёт решения — делать или нет)

1. Добавить колонку `message_id` в `sent_notifications` (эта таблица — контракт
   только этого этапа, кросс-командного согласования не требует)
2. При отправке (`process_user` в `sender.py`) сохранять `message_id` из ответа
   `bot.send_message()` вместе с `(tg_id, vacancy_id)`
3. Добавить админ-команду/скрипт «отозвать вакансию у всех, кому отправили» —
   проход по всем `(tg_id, message_id)` для конкретного `vacancy_id` и вызов
   `bot.delete_message()` (или `edit_message_text()`, если нужно не удалить, а
   заменить текст)

## Ограничения

- Telegram: `deleteMessage` в личных чатах работает только для сообщений младше
  **48 часов** — позже отозвать нельзя, даже зная `message_id`
- Для компактного дайджеста (`_build_compact_digest`, при >10 вакансиях) одна
  вакансия — это не отдельное сообщение, а строка внутри общего текста; отозвать
  такую вакансию отдельно нельзя, только отредактировать/переслать весь дайджест
  заново
- Задним числом (для уже отправленных до этой правки сообщений) ничего не
  восстановить — `message_id` для них потерян безвозвратно
